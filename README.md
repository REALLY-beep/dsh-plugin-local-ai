# DSH Local AI Workbench

Плагин для **DSH Desktop / DeepSeek Harness**, который добавляет в интерфейс раздел **Local AI** для локальных моделей в формате GGUF. Запуск моделей выполняет `llama.cpp` через `llama-server`; облачный API для генерации не используется.

## Что умеет

- Отдельная центральная панель Local AI, зарегистрированная через официальные слоты DSH `sidebar.panellist` и `main`. DSH сам размещает неподкреплённые панели в меню More; закрепление/расположение остаётся за интерфейсом DSH.
- Библиотека GGUF: рекурсивное обнаружение файлов во всех вложенных папках каталога моделей, добавление по полному пути, метаданные файла и квантования, сохранение каталога между перезапусками.
- Запуск и остановка одной модели через отдельный процесс `llama-server`, проверка `/health`, состояние и лог процесса.
- Настройки на уровне модели: контекст, GPU layers, CPU threads, batch size, temperature, top-p, top-k, repeat penalty, Flash Attention и Jinja templates.
- Регистрация каждой модели в нативном списке моделей DSH через provider `dsh-local-ai` в `llm-pi-ai`.
- Поиск публичных GGUF-репозиториев Hugging Face и загрузка выбранного файла прямо в настроенную папку моделей с прогрессом и отменой.
- Сервер привязан только к `127.0.0.1`; путь GGUF не передаётся клиентскому UI и не передаётся модели.

## Установка

### Вариант 1 — установить из GitHub

После публикации репозитория на GitHub загрузи **содержимое** распакованной папки (файл `package.json` должен лежать в корне репозитория). Затем открой Open DSH Terminal из меню трея и выполни:

```bash
dsh plugin --profile desktop add github:REALLY-beep/dsh-plugin-local-ai
```

Затем полностью перезапусти DSH Desktop, чтобы новый bundle попал в состав Loader. Команда `desktop` предназначена для DSH Desktop; не запускай её из обычной глобальной установки CLI — используй терминал, который открывается из трея DSH Desktop.

### Вариант 2 — установить локальную копию

Распакуй архив в постоянную папку. В терминале DSH Desktop выполни команду установки пакета из локального каталога:

```bash
dsh plugin --profile desktop add "C:/path/to/dsh-local-ai-workbench"
```

После установки перезапусти приложение. Для обычного профиля Web команда аналогична; в DSH Desktop без `--profile` используется активный профиль.

## Первичная настройка

1. Установи сборку **llama.cpp**, содержащую `llama-server` (для Windows обычно `llama-server.exe`). Плагин не скачивает исполняемый движок автоматически: это отдельная нативная программа с вариантами сборок под разные GPU.
2. Открой Local AI из левого меню DSH (при стандартном размещении — More → Local AI).
3. Во вкладке **Engine & Settings** укажи путь к `llama-server.exe` либо к каталогу, в котором он лежит. Если бинарный файл доступен через `PATH`, поле можно оставить пустым.
4. Укажи каталог хранения моделей и сохрани настройки. По умолчанию используется `$DSH_HOME/models` (обычно `~/.dsh/models`).
5. Во вкладке **Модели** добавь свой `.gguf` или просканируй папку. Во вкладке **Hugging Face** можно найти публичный GGUF-репозиторий и скачать выбранный файл.
6. Открой настройки нужной модели, выбери контекст и GPU layers под своё железо, сохрани и нажми **Запустить**.
7. Нажми **В DSH**, чтобы добавить активную модель в нативный селектор DSH. После этого запусти её и выбери `Local AI (llama.cpp)` в стандартном списке моделей.

## Рекомендуемая настройка ресурсов

- **GPU layers**: `0` — CPU-only; увеличивай постепенно, пока модель помещается в VRAM.
- **Context**: начинай с 4096–8192 токенов и повышай только при реальной необходимости. Большой контекст расходует дополнительную память.
- **Threads**: обычно количество физических ядер или немного меньше. Если CPU занят системой, уменьши значение.
- **Batch size**: 256–512 — разумная отправная точка; уменьшение может снизить пиковое потребление памяти.
- Для моделей с длинным контекстом или multimodal режимом фактические параметры и доступность функций зависят от выбранной сборки llama.cpp и архитектуры GGUF.

## Где хранятся настройки

- `$DSH_HOME/local-ai-workbench.json` — параметры движка и каталога.
- `$DSH_HOME/local-ai-models.json` — библиотека моделей и их индивидуальные параметры.
- Модели сохраняются в каталоге, указанном в **Engine & Settings**; удаление из библиотеки не удаляет GGUF-файл с диска.

На Windows, если переменная `DSH_HOME` не задана, используется `%USERPROFILE%\\.dsh`. На Linux/macOS — `~/.dsh`.

## Безопасность и сетевое поведение

- `llama-server` запускается с `--host 127.0.0.1`, а не на всех сетевых интерфейсах.
- Команда запуска собирается как массив аргументов процесса; shell не используется.
- API key хранится локально в файле настроек (на Unix-подобных системах файл создаётся с правами `0600`; на Windows действует ACL пользовательской папки). Если задать ключ, он также передаётся `llama-server` аргументом командной строки — не используй этот режим на общей многопользовательской машине.
- Сетевой запрос отправляется на Hugging Face только при явном поиске или скачивании. Инференс проходит через локальный `llama-server`.
- Плагин имеет доступ к файловой системе и процессам Host DSH — это нормальная граница для локального менеджера GGUF. Устанавливай только тот код, который готов запускать с правами DSH.

## Разработка и проверки

Требования: Node.js 20+ (DSH Desktop поставляет собственную среду), совместимая версия DSH и `llama.cpp`.

```bash
npm test
npm run check
```

`tests/logic.test.mjs` проверяет нормализацию настроек, генерацию аргументов без shell-интерпретации, идентификаторы моделей, проверку Hugging Face repository/file и построение download URL. `tests/model-scanner.test.mjs` проверяет рекурсивный поиск GGUF на нескольких уровнях вложенности, фильтрацию `mmproj`, проверку пути и отказ от обхода символических ссылок.

## Ограничения первой версии

- Одновременно работает один `llama-server` и одна активная GGUF-модель. В провайдер DSH публикуется только модель, которую ты последней добавил кнопкой **В DSH**; для переключения останови сервер, нажми **В DSH** у другой модели, запусти её и выбери её в селекторе DSH. Это не даёт отправлять запросы к незагруженной модели.
- Автоматическая установка/обновление llama.cpp не входит в релиз: сборки CPU/CUDA/Vulkan/Metal отличаются и требуют выбора под систему.
- Поиск Hugging Face работает с публичными репозиториями. Для приватных gated-моделей нужен отдельный механизм токенов, которого в этой версии нет.
- Поддержка мультимодальных `mmproj` и специальных режимов inference требует дополнительных параметров конкретной модели; в текущем UI реализован базовый текстовый запуск.
- Совместимость UI/Remote API проверяется на основе актуального публичного DSH plugin API, но полный запуск внутри конкретной установленной сборки DSH Desktop необходимо проверить после установки: в этой среде отсутствует сам DSH runtime.

## Проекты, которые изучались

- `PerryLink/dsh-local-ai` — Ollama-centric; другой backend и пользовательский сценарий.
- `Lbunc/dsh-local-llm-controller` — использует llama.cpp/llama-server, но в основном работает как контроллер двух модельных слотов в настройках; здесь вместо него сделана библиотека и самостоятельная панель управления.
- `Elantino/dsh-local-model` — ещё один вариант локального подключения; его сценарий не совпадает с LM Studio-style каталогом и управлением процессом.

Плагин не копирует исходный код перечисленных проектов. Он использует публичные контракты DSH, отдельные Host/Client половины и независимые UI/сервисы.
