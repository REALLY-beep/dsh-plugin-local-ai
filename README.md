# DSH Local AI Workbench

Плагин для **DSH Desktop / DeepSeek Harness**, который добавляет в интерфейс раздел **Local AI** для локальных моделей в формате GGUF. Запуск моделей выполняет `llama.cpp` через `llama-server`; облачный API для генерации не используется.

## Что умеет

Текущая версия: **0.1.7**. Панель и результаты сканирования имеют собственную вертикальную прокрутку внутри окна DSH.

- Отдельная центральная панель Local AI, зарегистрированная через официальные слоты DSH `sidebar.panellist` и `main`. DSH сам размещает неподкреплённые панели в меню More; закрепление/расположение остаётся за интерфейсом DSH.
- Библиотека GGUF: рекурсивное обнаружение файлов во всех вложенных папках каталога моделей, добавление по полному пути, метаданные файла и квантования, сохранение каталога между перезапусками.
- Запуск и остановка одной модели через отдельный процесс `llama-server`, проверка `/health`, состояние и лог процесса.
- Настройки на уровне модели: контекст, GPU layers, CPU threads, batch size, temperature, top-p, top-k, repeat penalty, Flash Attention и Jinja templates.
- Регистрация каждой модели в нативном списке моделей DSH через provider `dsh-local-ai` в `llm-pi-ai`.
- Значки возможностей разделяют декларации модели и фактическую поддержку плагином. Для Vision используется связка основной GGUF + выбранный совместимый `mmproj` + проверка image-input запросом к запущенному `llama-server`. Только после успешной проверки DSH получает `input: ['text', 'image']` для этой модели. Проверка привязана к размерам и времени изменения обоих GGUF-файлов и бинарника движка; при замене файлов/движка статус сбрасывается. Tools требуют Jinja и подходящего chat template; reasoning зависит от модели и шаблона. Audio, embeddings и rerank в DSH-провайдере пока не подключены.
- Каталог Hugging Face в стиле Models: поиск по имени/семейству, сортировка по популярности, загрузкам, лайкам и дате обновления; фильтры по числу параметров (B) и фактическому весу GGUF. Рекурсивное дерево репозитория читается постранично и привязывается к точной ревизии. При выборе Vision-модели можно выбрать `mmproj`; полные split-GGUF комплекты, выбранный проектор и основной файл скачиваются совместно. Каждый файл загружается во временную папку, сверяется с размером Hub API и только после успеха весь комплект атомарно перемещается в библиотеку. Поддерживаются прогресс и отмена без оставления частичных файлов.
- Сервер привязан только к `127.0.0.1`; полный путь основного GGUF остаётся на Host-стороне. Путь выбранного `mmproj` показывается только в локальной панели управления, чтобы пользователь мог проверить и изменить привязку. Ни один из этих путей не добавляется в сообщения чата или конфигурацию модели DSH.

## Установка

### Вариант 1 — установить из GitHub

После публикации репозитория на GitHub загрузи **содержимое** распакованной папки (файл `package.json` должен лежать в корне репозитория). Затем открой Open DSH Terminal из меню трея и выполни:

```bash
dsh plugin --profile desktop add github:REALLY-beep/dsh-plugin-local-ai#main
```

Затем полностью перезапусти DSH Desktop, чтобы новый bundle попал в состав Loader. Команда `desktop` предназначена для DSH Desktop; не запускай её из обычной глобальной установки CLI — используй терминал, который открывается из трея DSH Desktop.

### Вариант 2 — установить локальную копию

Распакуй архив в постоянную папку. В терминале DSH Desktop выполни команду установки пакета из локального каталога:

```bash
dsh plugin --profile desktop add "C:/path/to/dsh-local-ai-workbench"
```

После установки перезапусти приложение. Для обычного профиля Web команда аналогична; в DSH Desktop без `--profile` используется активный профиль.

## Контекст DSH и оценка памяти

В настройках каждой модели ползунок **Контекст** показывает ориентировочный размер KV-cache в GiB для текущего количества токенов. Расчёт читается из GGUF metadata (число слоёв, KV-heads, размер key/value head) и предполагает стандартный F16 cache K/V в llama.cpp. Это оценка только KV-cache, а не общего потребления памяти: веса модели, compute buffers, `mmproj`, allocator overhead и дополнительные state-space буферы считаются отдельно. Для гибридных SSM/Mamba архитектур оценка помечается как частичная. Если GGUF не содержит нужных метаданных, плагин не подставляет выдуманное число.

### Исправление compaction для небольших локальных контекстов

В некоторых версиях DSH `@deepseek-ai/dsh-compaction-basic` использует `headroomTokens: 65536` по умолчанию. Для локальных моделей с контекстом около 4K–16K это может сделать бюджет сжатия отрицательным и блокировать переключение модели. Профильный patch не может точечно изменить одноимённую запись внутри `preset-standard`: она вложена в состав Agent Preset, а patch-слой заменяет весь preset.

В архив включён готовый установщик `APPLY-CONTEXT-FIX.cmd` (внутри он запускает `scripts/Apply-DSH-LocalAI-ContextPatch.ps1`). Закрой DSH и запусти CMD-файл двойным щелчком. Установщик читает фактический встроенный preset текущей версии через `dsh --profile desktop --dump-default-config`, копирует **весь** `preset-standard` в профильный `cordis.patch.yml` и меняет только вложенные `compaction-basic.headroomTokens` и `compaction-basic.maxTokens` на `1024`. Все остальные инструменты, группы, prompts и параметры стандартного пресета сохраняются из текущей установки DSH.

Перед изменением создаётся резервная копия `cordis.patch.yml`. После записи установщик вызывает `dsh --profile desktop --dump-config` и проверяет, что изменённые значения реально присутствуют в итоговом preset. Если проверка не проходит (например, более поздний home-level patch перекрывает настройки), исходный файл автоматически восстанавливается, а скрипт выводит причину. Повторный запуск безопасен и не создаёт дублирующих строк.

Для ручного запуска из PowerShell:

```powershell
Set-Location "C:\путь\к\распакованной\папке\dsh-local-ai-workbench"
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\Apply-DSH-LocalAI-ContextPatch.ps1
```

Для текущей конфигурации пользователя (`contextWindow: 11776`, выходной резерв `maxTokens: 2944`) новые значения оставляют `11776 - 2944 - 1024 = 7808` токенов pressure budget вместо отрицательного бюджета с заводским headroom `65536`. Фактический порог compaction также учитывает `thresholdRatio` и токены системных инструкций/инструментов. Скрипт меняет только preset `standard`: модели, `local-ai-workbench.json`, `local-ai-models.json`, скачанные GGUF и список инструментов не удаляются и не редактируются. Поскольку профильный preset override является снимком встроенного списка плагинов, после крупных обновлений DSH повторно запусти установщик, чтобы переснять актуальный список.

## Первичная настройка

1. Установи сборку **llama.cpp**, содержащую `llama-server` (для Windows обычно `llama-server.exe`). Плагин не скачивает исполняемый движок автоматически: это отдельная нативная программа с вариантами сборок под разные GPU.
2. Открой Local AI из левого меню DSH (при стандартном размещении — More → Local AI).
3. Во вкладке **Engine & Settings** укажи путь к `llama-server.exe` либо к каталогу, в котором он лежит. Если бинарный файл доступен через `PATH`, поле можно оставить пустым.
4. Укажи каталог хранения моделей и сохрани настройки. По умолчанию используется `$DSH_HOME/models` (обычно `~/.dsh/models`).
5. Во вкладке **Модели** добавь основной `.gguf` или просканируй папку. Если рядом ровно один `mmproj-*.gguf`, он будет предложен автоматически; если проекторов несколько, выбери правильный вручную в настройках модели. Во вкладке **Hugging Face** ищи семейства моделей (например, `Qwen3`, `Gemma`, `Llama`), выбирай квантование и при необходимости совместимый `mmproj`. Для split-моделей скачивается полный комплект частей.
6. Открой настройки модели, проверь путь к `mmproj` (если это Vision-модель), выбери контекст и GPU layers под своё железо, сохрани и нажми **Запустить**.
7. Для Vision дождись статуса «Сервер запущен» и нажми **Проверить Vision**. Плагин отправит небольшой встроенный тестовый PNG на локальный `/v1/chat/completions`. Успех подтверждает, что сервер принял image-input; он не оценивает качество распознавания. Только после этого плагин регистрирует `input: ['text', 'image']` в DSH.
8. Нажми **В DSH**, если модель ещё не зарегистрирована, затем создай новый чат или выбери её в селекторе текущего чата. Существующие сессии сохраняют старые provider/model ID, поэтому после переключения GGUF они могут ссылаться на предыдущую модель.

## Рекомендуемая настройка ресурсов

- **GPU layers**: `0` — CPU-only; увеличивай постепенно, пока модель помещается в VRAM.
- **Context**: начинай с 4096–8192 токенов и повышай только при реальной необходимости. Большой контекст расходует дополнительную память.
- **Threads**: обычно количество физических ядер или немного меньше. Если CPU занят системой, уменьши значение.
- **Batch size**: 256–512 — разумная отправная точка; уменьшение может снизить пиковое потребление памяти.
- Для моделей с длинным контекстом или multimodal режимом фактические параметры и доступность функций зависят от выбранной сборки llama.cpp и архитектуры GGUF.

## Где хранятся настройки

- `$DSH_HOME/local-ai-workbench.json` — параметры движка и каталога.
- `$DSH_HOME/local-ai-models.json` — библиотека моделей и их индивидуальные параметры.
- Модели сохраняются в каталоге, указанном в **Engine & Settings**; удаление из библиотеки не удаляет GGUF-файл с диска.

На Windows, если переменная `DSH_HOME` не задана, используется `%USERPROFILE%\\.dsh`. На Linux/macOS — `~/.dsh`.

## Безопасность и сетевое поведение

- `llama-server` запускается с `--host 127.0.0.1`, а не на всех сетевых интерфейсах.
- Команда запуска собирается как массив аргументов процесса; shell не используется.
- API key хранится локально в файле настроек (на Unix-подобных системах файл создаётся с правами `0600`; на Windows действует ACL пользовательской папки). Если задать ключ, он также передаётся `llama-server` аргументом командной строки — не используй этот режим на общей многопользовательской машине.
- Сетевой запрос отправляется на Hugging Face только при явном поиске или скачивании. Инференс проходит через локальный `llama-server`.
- Плагин имеет доступ к файловой системе и процессам Host DSH — это нормальная граница для локального менеджера GGUF. Устанавливай только тот код, который готов запускать с правами DSH.

## Разработка и проверки

Требования: Node.js 20+ (DSH Desktop поставляет собственную среду), совместимая версия DSH и `llama.cpp`.

```bash
npm test
npm run check
```

`tests/logic.test.mjs` проверяет нормализацию настроек, генерацию безопасных аргументов, идентификаторы моделей, Hub URL/ревизии, постраничный обход дерева одного репозитория, фильтры параметров/веса, размеры файлов, выбор `mmproj` и комплекты shard-файлов. `tests/model-scanner.test.mjs` проверяет рекурсивное обнаружение GGUF, локальное связывание проекторов и split-шардов, запрет обхода символических ссылок. `tests/release-regression.test.mjs` проверяет Remote-дескрипторы, DSH-регистрацию, image-input probe, fingerprint файлов/движка и атомарную загрузку комплекта.

## Ограничения первой версии

- Одновременно работает один `llama-server` и одна активная GGUF-модель. В провайдер DSH публикуется только модель, которую ты последней зарегистрировал кнопкой **В DSH**. После смены модели создай новый чат или выбери актуальную запись в селекторе текущего чата: DSH сохраняет model ID уже начатой сессии. Если появляется `no configured model "gguf-…"`, сравни ID ошибки с ID зарегистрированной модели в Local AI; повторно нажми **В DSH** для нужной модели и открой новый чат.
- Автоматическая установка/обновление llama.cpp не входит в релиз: сборки CPU/CUDA/Vulkan/Metal отличаются и требуют выбора под систему.
- Поиск Hugging Face работает с публичными репозиториями. Для приватных gated-моделей нужен отдельный механизм токенов, которого в этой версии нет. Для Vision можно выбрать только `mmproj`, опубликованный в том же репозитории и той же ревизии, что и основной GGUF; если проектор лежит в другом репозитории, его пока нужно скачать вручную и привязать по локальному пути.
- Vision поддерживается через `mmproj` и OpenAI-compatible image input llama-server. Не все архитектуры, проекторы и сборки llama.cpp совместимы между собой: фактический статус определяется тестовым изображением. Проверка подтверждает принятие изображения сервером, но не качество ответов модели. Модели с полностью встроенным визуальным трактом без отдельного `mmproj` в этой версии автоматически не включаются как Vision.
- Audio, embeddings и rerank не подключены к DSH-провайдеру плагина. Tools остаются условной возможностью и требуют совместимого chat template и корректной регистрации инструментария в DSH.
- Совместимость UI/Remote API проверяется на основе актуального публичного DSH plugin API, но полный запуск внутри конкретной установленной сборки DSH Desktop необходимо проверить после установки: в этой среде отсутствует сам DSH runtime.

## Проекты, которые изучались

- `PerryLink/dsh-local-ai` — Ollama-centric; другой backend и пользовательский сценарий.
- `Lbunc/dsh-local-llm-controller` — использует llama.cpp/llama-server, но в основном работает как контроллер двух модельных слотов в настройках; здесь вместо него сделана библиотека и самостоятельная панель управления.
- `Elantino/dsh-local-model` — ещё один вариант локального подключения; его сценарий не совпадает с LM Studio-style каталогом и управлением процессом.

Плагин не копирует исходный код перечисленных проектов. Он использует публичные контракты DSH, отдельные Host/Client половины и независимые UI/сервисы.
